## 생산 SENS 스트림의 native 검사

Windows와 Linux에서 실제 [SENS_ATMOS.hpp](../../../src/px4/sens_atmos/SENS_ATMOS.hpp)를 포함한 native stub harness를 실행했고 **각각 79개 검사**를 통과했습니다. 검사한 생산 헤더 SHA256은 다음과 같습니다.

```text
90e5af2264cb72b56ed0ada9a9964fae5dac3c4056938e6255f5b517ba3fcf4e
```

검사 범위는 다음과 같습니다.

- MAVLink 1에서는 payload 전송과 uORB 표본 소비가 모두 0.
- MAVLink 2의 유효한 새 표본은 측정 boot 시각·°C·%RH를 그대로 송신.
- instance 0 하나만 구독.
- 센서가 미광고 상태이거나 새 값이 없으면 송신하지 않음.
- 0·미래·1초 초과 과거 시각, NaN/Inf, 절대영도 아래 온도, 0–100 %RH 밖 습도를 거부.
- 경계값과 실제 채널 번호 전달 확인.

이 검사는 실물 전기 신호나 센서 교정 정확도, flight stack 전체의 스케줄링을 검증하지 않습니다.

## 실행 비용과 제한

센서 한 주기에서 I²C 4회, 온습도 CRC 2개와 부동소수점 변환 2개를 처리합니다. 100 kHz에서 ACK를 포함한 공칭 144클록은 1.44 ms이며 10 Hz에서 공칭 버스 시간의 약 1.44%입니다. 13 ms 센서 변환은 다음 callback 예약으로 기다립니다. bus 경합·START/STOP·스케줄링·오류 타임아웃을 포함한 최악 실행 시간 측정은 아닙니다.

SENS 스트림은 표본 하나를 처리하는 O(1) 경로입니다. 개선판은 기존 MAVLink 루프마다 새 generation 여부를 확인하고 새 표본이 있을 때만 보냅니다. 실제 상수 MAVLINK_MIN_INTERVAL=1500, MAVLINK_MAX_INTERVAL=10000 µs에 따라 설정된 대기를 기준으로 이론상 약 100–667회/초이며 새 태스크나 타이머를 만들지 않습니다. 지연 시 더 느려질 수 있어 최소 100 Hz 보장은 아닙니다. 정상 반복마다 O(1) generation 확인 한 번을 하고, 실제 약 10 Hz 새 표본에 대한 직렬화 빈도는 그대로입니다. 개별 확인의 실물 CPU 시간은 측정하지 않았습니다.

무서명 MAVLink 2에서 최대 28 B × 10 Hz = 280 B/s, 서명 시 410 B/s입니다. unlimited 스트림은 rate_mult 계산에서 대역 예약이 0이며, 관찰된 USB 100000 B/s 할당의 0.28–0.41%를 사용합니다. 저속 무선 모드의 기존 rate·프로토콜·baud는 변경하지 않았습니다. 기존 HYG의 %RH→0.01 %RH 변환 버그만 표준에 맞게 교정했습니다.

실제 고속 이동에서 센서 물리 응답 지연, 장착 위치, GNSS 오차와 시간 불확실성은 별도 문제입니다. 측정 시각의 µs 표현을 µs 정확도로 해석하거나, GPS fix가 없는데 위치를 복원된 관측값처럼 표시해서는 안 됩니다.

## 실물·수집기·TCP 검증

아래의 ‘최종 개선판 실물 확인’에 같은 펌웨어 SHA256으로 수행한 업로드·자동 시작·USB 수신·C 서버·서버 TUI·설정 비교·마지막 센서 상태를 기록했습니다. 위 빌드 결과나 이전 초안의 결과로 최종 실물 검증을 대신하지 않습니다.

GPS fix나 UTC가 없으면 서버 출력의 위치·UTC는 null이어야 합니다. 관측 원본은 파일에 저장하지 않고 검사 중 메모리에만 유지합니다. 파라미터 백업은 관측 자료와 별개이며 private 경로에 보관하고 소스 Git이나 배포물에서 제외합니다.


## 실물에서 발견한 고정 주기 문제와 개선판

초안 펌웨어 SHA256 `264a161aff717ac88e58d815a47370b12cbab377ca38fc39d818faee65b9d158`의 7초 USB 관찰에서는 SENS 63프레임, HYG 0프레임을 받았습니다. 수신된 측정 시각의 간격은 최소 100233 / 중앙값 100310 / 최대 200677 µs였고, 측정 시각으로 계산한 수신률은 9.364 Hz였습니다. 약 두 센서 주기에 해당하는 간격이 나타나 일부 원본 표본이 빠졌다는 근거가 있습니다.

코드상 센서와 고정 송신을 각각 약 10 Hz로 예약하면 비동기 위상과 스케줄링 때문에 송신이 늦어지는 사이 1슬롯 uORB의 이전 값이 최신 값으로 대체될 수 있습니다. 이를 줄이기 위해 기존 GPS_RAW_INT와 같은 `unlimited_rate` 패턴으로 변경했습니다. 새 값이 없으면 송신하지 않으므로 이 설정은 센서 측정률이나 실제 전송량을 루프 반복률로 올리는 설정이 아닙니다.

이 개선으로 같은 주기의 송신 gate를 제거했지만 uORB 큐 깊이는 여전히 1입니다. source 주기보다 긴 태스크 정체·전송 혼잡 등 모든 조건에서 표본 보존을 보증하지 않습니다. 개선판의 실물 빈도와 차압계·수집기·TCP 회귀는 루트 작업자가 별도로 확인합니다.

초안으로 실행한 수집기→시험 서버와 TUI 검사는 각각 통과했고, 루트 보고 기준 12 HTTP/ACK, 원본 224개(온습도 112쌍), 큐·드롭·중복 0을 확인했습니다. 이 결과는 초안 시험의 해당 구간이며 개선판 전체 경로 검증으로 대신하지 않습니다. GPS fix/UTC가 없어 위치·UTC는 null로 처리했습니다. 원본 관측값을 파일에 저장하지 않았습니다.

초안 펌웨어·ELF·build-info·패치·manifest·문서는 `build/px4-fmu-v6c-v1.16-weather/archive/stream-10hz/`에 보존했습니다. 현재 표의 업로드 파일은 개선판 `eb3b57b0...`이며, 이전 결과와 해시를 섞어 해석하지 않습니다.


센서의 물리 응답 지연과 연속 표본 사이의 상관이 있으므로, 1초 구간 표본분산은 그 구간 값의 산포이며 센서 정확도·교정 오차를 나타내는 정확도 분산으로 대체할 수 없습니다. [제조사 응답시간·정확도 정의](https://sensirion.com/media/documents/643F9C8E/63A5A436/Datasheet_SHTC3.pdf)

## 최종 개선판 실물 확인

루트 작업자가 시동 해제 상태와 설정 백업을 확인한 뒤 SHA256 `eb3b57b0627b5c43e80c61de76fc5ad62de24d3a125daf3cdcfee27022cb54b5`를 대조해 업로드했습니다. Erase·Program·Verify 100%와 재부팅까지 **26.813초**였으며, 저장된 `SENS_EN_SHTC3=1`에 의해 I²C2 지속 드라이버의 부팅 자동 시작에 성공했습니다.

USB MAVLink 2를 7초 관찰한 회차에서는 **SENS 70프레임 / HYG 0프레임**을 받았습니다. 측정 시각 간격은 최소 **100274**, 중앙값 **100307**, 최대 **100560 µs**이고, 측정 시각 기준 수신률은 **9.9672165 Hz**였습니다. 초안에서 보였던 약 두 주기 간격이 이번 회차에서는 없어졌습니다. 모든 운용 조건에서 표본 손실이 없다는 보장은 아닙니다.

실제 C 시험 서버의 TCP 21000 경로에서는 **12 requests / HTTP 204 수락 12 / 표시 records 12 / rejected 0**을 확인했습니다. 원본 244개는 온습도 122쌍이고, 중복·pending·큐 드롭·원본 드롭은 0이었습니다. 서버 도착 구간의 최소 전송 간격은 1000 ms로 기본 1초 묶음 전송을 확인했습니다. 수신 원본에서 구간 평균·표본분산 등을 독립 계산한 검사도 통과했습니다.

GPS fix는 0이었습니다. 따라서 위치 244개 전부와 UTC/clock 연결값은 null, 알려지지 않은 불확도도 null로 유지했으며 품질 플래그는 `0x24000000`이었습니다. 압력 관측 metric은 0개로, SENS_ATMOS에 없는 압력값을 만들어 넣지 않았습니다. 실제 관측값은 검사 메모리에만 유지했습니다.

설정 비교에서는 이전 파라미터 1178개 모두 타입과 원시 wire 값이 같고 누락이 없었습니다. 새 항목은 예상한 `SENS_EN_SHTC3` INT32 값 1 하나이며, 최종 펌웨어 업로드 전후의 1179개 설정도 모두 같았습니다. 기존 비행·교정 설정이 바뀌었다고 추정해 넘기지 않고 해당 목록을 비교했습니다.

최종 서버 TUI도 실제 C 시험 서버를 대상으로 **12 requests / HTTP 204 12 / records 12 / rejected 0 / pending 0**을 확인했습니다. `src/tests/physical_weather_tui_check.py`로 실제 콘솔 화면의 SI 단위, 통계, boot 시각, 위치 미상 표시까지 검사했습니다. 초안 TUI 결과를 개선판 결과로 대신하지 않았습니다.

마지막 상태에서는 SHTC3 표본 **3112개**, I/O·CRC·ID·timing 오류와 reset이 모두 **0**이었습니다. 같은 부팅 세션의 MS4525 차압계는 읽기 **23660회**, 통신 오류와 fault가 모두 **0**이었습니다. 전체 시험 시간 밖의 동작이나 비행 환경까지 무간섭을 보증하는 결과는 아닙니다.

기존 성능 카운터를 한 번 읽었을 때 `mavlink: tx run interval` 두 인스턴스는 평균/최대가 각각 **3013.41 / 5966 µs**, **10005.89 / 18837 µs**였고, `tx run elapsed`는 **142.99 / 3098 µs**, **113.69 / 1616 µs**였습니다. 이름이 같은 인스턴스 둘을 USB·무선으로 임의 대응하지 않았습니다.

`shtc3: cycle`은 callback 15561회에서 평균 **314.27 µs**, 최소 **1 µs**, 최대 **714 µs**였습니다. 이는 상태 기계의 전체 callback 벽시간이며 I²C 대기 등을 포함합니다. 개선 전 baseline이 없어 추가 CPU 시간 차이를 실측한 값이 아니고, 최악 실행 시간 보증도 아닙니다.

검사 후 COM5를 해제했고, 시험용 서버와 수집기 자식 프로세스는 모두 종료했습니다. 실제 원본 온습도·좌표 관측값을 파일에 저장하지 않았습니다. 위 숫자는 검증 요약이며 개인 설정 백업은 private 경로에 보관하고 소스·배포물에서 제외합니다.
