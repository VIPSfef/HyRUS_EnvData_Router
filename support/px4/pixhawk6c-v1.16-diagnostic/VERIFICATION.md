# 진단 구성 검증 기록 · 2026-10-25

이 기록은 소스 검사·호스트 시험·ARM 빌드 결과입니다. 실물 펌웨어 업로드, 전용 제품 ID 조회, SHTC3 온습도 측정은 수행하지 않았습니다. 전원·SDA/SCL 파형·실물 버스 무간섭도 측정하지 않았습니다.

## 기준과 패치

- PX4 `v1.16.0`: `6ea3539157ca358c70a515878b77077af7d4611d`.
- NuttX: `886acbbdb4f061e5c0ce1a76afbcfa7cb7df9849`; apps: `e37940d8535f603a16b8f6f21c21edaf584218aa`.
- MAVLink 원본 서브모듈: `5bfd76d80281f6027134e854aafe6cb3dbfbe9e1`; dialect 변경 없음.
- 패치 한 개: 보드 설정의 두 모듈 활성화와 `drv_sensor.h`의 SHTC3 device type `0xB9` 등록만 변경.
- `rc.sensors`·기존 텔레메트리·센서 드라이버 원본·비행 기능 제거 없음. SHTC3 자동 시작 없음.
- 공유 드라이버 6개 + probe 4개 소스는 manifest 및 실제 ARM 빌드 입력의 SHA256이 일치.

정확한 파일 해시는 [overlay-manifest.json](overlay-manifest.json)에 있고, 바이너리·서브모듈·실제 빌드 입력 기록은 작업 저장소 `build/px4-fmu-v6c-v1.16/shtc3-diagnostic-build-info.json`에 있습니다.

## 적용 도구와 진단 코어

- 기존 `apply_overlay.py` 안전성 회귀 검사: Windows에서 10/10 통과. 임시 Git 저장소만 변경.
- 실제 기준 PX4 Git 객체를 공유한 임시 새 체크아웃에서 전용 manifest의 12개 대상 파일 검사·적용·재적용 통과.
- 기본 `--check`가 원본 파일을 바꾸지 않음, 재적용 시 변경 0개, `sitl` 프로필 거부, 수정된 기존 모듈 덮어쓰기 거부를 확인.
- 실제 ARM 빌드 트리에 대해 최종 manifest `--check`: 변경 0개. 이 검사는 파일 쓰기 없음.
- 최종 진단 코어: Windows Clang 22, Linux GCC 13.3에서 각각 CMake 빌드·CTest 통과. 두 플랫폼 모두 1,444,257개 검사, 결과 구조체 20바이트.
- 제품 ID 65,536개·24비트 단일 오류·각 I/O와 대기 실패·정확한 명령/대기 순서·SLEEP 실패 별도 표시를 시험. 가짜 버스이며 COM/I²C 실물 접근 없음.
- 독립 소스 리뷰에서 명시적 버스·0x70 고정·최대 4회 전송·오류 재시도/`I2C_RESET` 호출 없음·ID 및 CRC 확인 후에만 MATCH/SLEEP를 확인.

## 공유 버스의 플랫폼 계약

위 NuttX 커밋 `arch/arm/src/stm32h7/stm32_i2c.c`를 직접 읽어 확인했습니다.

- 초기화는 bus 참조 수를 증가시키며 기존 참조가 있으면 하드웨어를 다시 초기화하지 않음(2810행 부근).
- 해제는 자신이 잡은 참조만 감소시키며 다른 드라이버 참조가 남으면 인스턴스만 해제(2851행 부근).
- 전송은 기존 bus semaphore로 직렬화되고 완료/오류 경로에서 해제(2514행·2494행 부근).
- 각 전송의 주파수를 메시지에서 적용(2305행 부근). 속도 변경 시 컨트롤러 내부 PE 토글은 플랫폼 구현의 일부이며, 이를 명시적 `I2C_RESET` 버스 복구 호출과 구분.

이는 구현 계약 확인입니다. 센서 배선·실물 버스 응답에 관한 시험 결과로 확대 해석하지 않습니다.
