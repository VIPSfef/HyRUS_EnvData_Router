# 진단 구성 검증 기록 · 2026-10-25

이 기록은 소스 검사·호스트 시험·ARM 빌드와 승인 후 실물 설치·단발 제품 ID 확인 결과입니다. 실물 SHTC3 온습도 변환·정확도·SENS_ATMOS/TCP 전송은 이번에 검증하지 않았습니다. 전원·SDA/SCL 파형도 측정하지 않았으며, 같은 부팅 세션의 차압계 상태 전후 비교를 전체 운용 조건의 무간섭 보증으로 확대하지 않습니다.

## 기준과 패치

- PX4 `v1.16.0`: `6ea3539157ca358c70a515878b77077af7d4611d`.
- NuttX: `886acbbdb4f061e5c0ce1a76afbcfa7cb7df9849`; apps: `e37940d8535f603a16b8f6f21c21edaf584218aa`.
- MAVLink 원본 서브모듈: `5bfd76d80281f6027134e854aafe6cb3dbfbe9e1`; dialect 변경 없음.
- 패치 한 개: 보드 설정의 두 모듈 활성화와 `drv_sensor.h`의 SHTC3 device type `0xB9` 등록만 변경.
- `rc.sensors`·기존 텔레메트리·센서 드라이버 원본·비행 기능 제거 없음. SHTC3 자동 시작 없음.
- 공유 드라이버 6개 + probe 4개 소스는 manifest 및 실제 ARM 빌드 입력의 SHA256이 일치.

정확한 파일 해시는 [overlay-manifest.json](overlay-manifest.json)에 있고, 바이너리·서브모듈·실제 빌드 입력 기록은 작업 저장소 `build/px4-fmu-v6c-v1.16/shtc3-diagnostic-build-info.json`에 있습니다.

## 적용 도구와 진단 코어

- 기존 `apply_overlay.py` 안전성 회귀 검사: Windows에서 10/10 통과. 임시 Git 저장소만 변경.
- 실제 기준 PX4 Git 객체를 공유한 임시 새 체크아웃에서 전용 manifest의 12개 대상 파일 검사·적용·재적용 통과.
- 기본 `--check`가 원본 파일을 바꾸지 않음, 재적용 시 변경 0개, `sitl` 프로필 거부, 수정된 기존 모듈 덮어쓰기 거부를 확인.
- 실제 ARM 빌드 트리에 대해 최종 manifest `--check`: 변경 0개. 이 검사는 파일 쓰기 없음.
- 최종 진단 코어: Windows Clang 22, Linux GCC 13.3에서 각각 CMake 빌드·CTest 통과. 두 플랫폼 모두 1,444,257개 검사, 결과 구조체 20바이트.
- 제품 ID 65,536개·24비트 단일 오류·각 I/O와 대기 실패·정확한 명령/대기 순서·SLEEP 실패 별도 표시를 시험. 가짜 버스이며 COM/I²C 실물 접근 없음.
- 독립 소스 리뷰에서 명시적 버스·0x70 고정·최대 4회 전송·오류 재시도/`I2C_RESET` 호출 없음·ID 및 CRC 확인 후에만 MATCH/SLEEP를 확인.

## 공유 버스의 플랫폼 계약

위 NuttX 커밋 `arch/arm/src/stm32h7/stm32_i2c.c`를 직접 읽어 확인했습니다.

- 초기화는 bus 참조 수를 증가시키며 기존 참조가 있으면 하드웨어를 다시 초기화하지 않음(2810행 부근).
- 해제는 자신이 잡은 참조만 감소시키며 다른 드라이버 참조가 남으면 인스턴스만 해제(2851행 부근).
- 전송은 기존 bus semaphore로 직렬화되고 완료/오류 경로에서 해제(2514행·2494행 부근).
- 각 전송의 주파수를 메시지에서 적용(2305행 부근). 속도 변경 시 컨트롤러 내부 PE 토글은 플랫폼 구현의 일부이며, 이를 명시적 `I2C_RESET` 버스 복구 호출과 구분.

위 내용은 소스에서 확인한 구현 계약입니다. 아래에 별도로 기록한 실물 단발 결과와 구분하며, 전기 배선과 전원 품질에 대한 검증으로 확대하지 않습니다.

- 컴파일러: `arm-none-eabi-gcc 13.2.1 20231009`. 연결된 기존 펌웨어가 보고한 GCC 9.3.1과 다름.
- 실제 최종 ELF에 `shtc3_main`, `shtc3_probe_main`, `ms4525do_main`, `ms5611_main`, `ist8310_main` 심볼이 포함됨.
- FLASH: 1,921,584 / 1,966,080 바이트(97.74%); 남은 공간 44,496바이트.
- AXI SRAM 정적 할당: 61,964 / 524,288 바이트(11.82%). 런타임 heap·stack 최댓값은 검증하지 않음.
- `.px4` 컨테이너 `magic=PX4FWv1`, `board_id=56`, `summary=PX4FMUv6C` 확인. 압축 image를 메모리에서 풀어 실제 image 크기와 SHA256도 build-info와 대조함.
- `.px4` 1,807,136바이트 SHA256: `694b92bad55477b01624222ffcb0aeae1c1c9ff42a8d4a096fd8e492e24f9d76`.

## 승인 후 실물 설치

- 연결 보드: Pixhawk 6C, 업로더 `board_id=56`, bootloader revision 5.
- 위 SHA256의 진단 `.px4`를 사용했고 Erase / Program / Verify가 각각 100%로 완료된 뒤 재부팅함. 업로더 전체 소요 시간 26.781초.
- 시동 해제 상태에서 검사. 설치 후 `ver`가 PX4 커밋 `6ea3539157ca358c70a515878b77077af7d4611d`, GCC 13.2.1, NuttX 커밋 `886acbbdb4f061e5c0ce1a76afbcfa7cb7df9849`를 보고함.
- OS 버전 표시는 `12.12.0`. 이 원본 PX4의 `src/lib/version/px_update_git_header.py` 130–132행은 현재 HEAD에 해당하는 태그 대신 저장소 전체 NuttX 태그 중 최대 버전을 고름. 복제본에 새 태그가 포함되어 `v12.12.0` 라벨이 생성됐으며, 생성 헤더의 실제 `NUTTX_GIT_VERSION_STR`와 깨끗한 NuttX HEAD는 위 고정 커밋과 일치함. NuttX 코드를 새 버전으로 교체한 결과가 아님.
- 진단 이후 COM5 연결을 모두 해제함.

## 실물 단발 SHTC3 식별

명령 `shtc3_probe -b 2`를 한 번 실행했습니다. SHTC3 지속 드라이버는 전후 모두 `Not running` 상태를 유지했고, 온습도 측정이나 uORB 발행을 시작하지 않았습니다.

| 항목 | 결과 |
|---|---|
| 버스 / 주소 / 주파수 | I²C 2 / `0x70` / 100 kHz |
| result / stage | `MATCH` / `COMPLETE` |
| 제품 ID | `0x0887` |
| 수신 CRC / 계산 CRC | `0x5B` / `0x5B` |
| operation_rc | 0 |
| SLEEP / sleep_rc | `OK` / 0 |
| 이번 실행 elapsed | 4,455 µs |

실제 ID `0x0887`은 제품 마스크 `(ID & 0x083F) == 0x0807`을 만족하고 CRC도 일치합니다. 이 결과는 SHTC3 계열 장치와 정식 절차로 통신했음을 확인합니다. 고유 일련번호·온습도 교정·공급 전압 품질을 확인한 것은 아닙니다. 4,455 µs는 해당 한 번의 실행 시간이며 최악 실행 시간이 아닙니다.

## 같은 부팅 세션의 차압계 전후 상태

전용 조회 직전과 직후의 동일 부팅 세션에서 MS4525DO 드라이버(I²C 2, `0x28`) 상태를 비교했습니다.

| 항목 | 조회 직전 | 조회 직후 |
|---|---:|---:|
| 읽기 수 | 1,079 | 1,105 |
| 통신 오류 수 | 0 | 0 |
| fault 수 | 0 | 0 |

읽기가 26회 증가하는 동안 이 상태 수치의 추가 오류는 없었습니다. 별도로 업로드 직전에는 차압계가 `Not running`이었고 재부팅 후 `Running`이었으므로, 업로드 전후 전체 상태를 연결해 오류 감소나 무간섭의 인과 효과를 주장하지 않습니다. 위 비교 범위는 단발 probe 전후의 같은 부팅 세션입니다.

## 설정 보존과 저장 범위

- 파라미터 광고 수: 업로드 전 1,177개, 업로드 후 1,178개.
- 기존 이름 1,177개 전부 타입과 원시 wire 값이 동일. 변경 0개, 누락 0개.
- 새로 광고된 이름은 `SENS_DPRES_REV` 하나이며 `type=6`(`INT32`), 값 0. 이름으로 비교했으며 개수 증가만 보고 SHTC3 파라미터라고 추정하지 않음.
- `SENS_EN_SHTC3`는 이번 실물 광고 목록에 없음. 공유 모듈 YAML의 기본값 정의와 실물의 광고 목록은 구분함. 진단판 `rc.sensors`에 자동 시작 hook은 없음.
- 파라미터 비교는 RAM에서 수행했고 개인 설정 백업은 배포물·소스 Git에 포함하지 않음.
- 관측 온도·습도·차압 값은 파일에 저장하지 않음. 문서에는 상태·구성·진단 결과만 기록함.

이번 실물 검증 범위는 설치·부팅·설정 비교·전용 제품 ID/CRC 확인과 단발 전후 차압계 상태입니다. 비행 검증, 장시간 안정성, SHTC3 온습도 변환·정확도, 실물 SENS_ATMOS/TCP 수집은 남아 있습니다.
