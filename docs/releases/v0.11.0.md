# mavlink_telemetry_data_router 0.11.0

Windows x64·Linux x64에서 시리얼 MAVLink 센서를 수집하고 HTTP API와 선택적인 UDP 백업으로 전달하는 배포본입니다. 기존 온습도 공간 집계와 JSON schema 식별자는 유지합니다.

## 변경점

- **저장소 역할 분리:** `HyRUS_EnvData_Router`는 호스트 MAVLink 수신·해독·집계·서버 전송을 담당합니다. 기존 I²C 드라이버·PX4 uORB·MAVLink 발행·펌웨어 패치를 `HyRUS_EnvData_Px4`로 분리하고 [캐리어 규약](../PX4_MAVLINK_CONTRACT.md)을 정리했습니다. 시험 서버는 선택 진단 도구입니다.
- **HTTP 요청 분산:** `http_min_interval_ms=500`을 기본으로 각 요청 완료 뒤 간격을 지킵니다. 측정·상태·재시도·종료와 설정 재시작 전송을 합쳐 초당 최대2회 수준으로 분산하고, 401·403·429에는1초부터 최대30초까지 공통 대기를 늘립니다. 미확인 자료는 RAM에 남으며 UDP 백업은 독립적으로 계속됩니다. 403의 원인을 응답 코드만으로 인증 또는 요청 제한으로 단정하지 않습니다.

- **COM/tty 자동 탐색:** 존재하는 포트를 설정한 기본 baud로 먼저 확인한 뒤 나머지 지원 속도를 탐색합니다. 링크가 끊기면 포트 목록을 다시 확인합니다.
- **QGC 중계:** 선택한 시리얼의 원본 MAVLink를 기본 `127.0.0.1:14550`으로 전달하고, QGC 요청을 같은 시리얼로 돌려보냅니다. 공식 MAVLink C 라이브러리의 고정 버전을 소스에 포함합니다.
- **읽기 쉬운 상태 화면:** 바뀐 줄만 갱신하며, 배터리 전압·잔량을 상단에 표시합니다. 하트비트와 일반 데이터 상태, 각각의 수신 경과 시간, 추정 패킷 누락을 구분합니다. GPS/ESTGPS 출처는 유지하고 유효성·경과 시간을 따로 표시합니다.
- **기체·센서 상태 보고:** `status_interval_ms=10000`이면 새 표본이 없어도 약10초마다 마지막 센서 값과 연결 상태를 별도 보고합니다. 과거 값을 새 측정으로 집계하지 않습니다. 시험 서버는 온습도·위치·키/ID 수·도착 순서·마지막 수신 경과 시간을 중심으로 표시합니다.
- **선택적인 MAVLink 전송률 제어:** 실측 대역폭과 UART 한도, ACK·추정 손실을 고려하여 GPS·온습도·대기속도를 우선하고 부차 스트림을 조절합니다. 기본 설정에서는 비활성화입니다.
- **UDP 즉시 송신과 TCP 메모리 대기열:** UDP 백업을 켜면 수락한 실시간 센서 표본마다 송신을 시도합니다. HTTP는 설정 주기에 RAM 대기열을 묶어 보내고204 확인 후 해제합니다. 대기열은 기본 **1GiB**이며 `tcp_buffer_max_mb`로 변경할 수 있습니다. UDP 기본 포트는 HTTP TCP 포트+1입니다.
- **직접 토큰 입력과 재시작:** TUI47번 `token`에 Bearer 토큰을 가려서 입력하고 `r`로 저장·적용합니다. Windows에서는 현재 사용자의 DPAPI로 암호화 저장하고, Linux에서는 소유자 전용0600 설정 파일에 저장합니다. 비우면 `token_env`를 사용합니다. URL이 같으면 새 토큰으로 기존401 대기열부터 재전송합니다.
- **URL 편집 표시:** `h`, `http:`처럼 아직 완성되지 않은 주소도 입력 중에는 그대로 표시하고, Enter로 확정할 때 검증합니다. 주소 안의 인증정보·쿼리·fragment는 계속 가립니다.
- **배포 구성 정리:** 라우터·시험 서버 실행 스크립트, 설정 예제, 서버 API와 제3자 라이선스 고지를 OS별 폴더에 함께 제공합니다. 첨부용 압축 파일에는 SHA256 목록과 manifest가 동봉됩니다.

## 실행과 설정

Windows는 배포 폴더의 `Start-Router.cmd`, Linux는 `./start-router.sh`로 실행합니다. 시험 서버는 `Start-Test-Server.cmd` 또는 `./start-test-server.sh`로 따로 켭니다. 라우터는 하나만 실행하여 같은 시리얼 포트를 중복 점유하지 않도록 합니다.

Windows x64는 시스템 UCRT를 사용하며 추가 MinGW DLL이 필요하지 않습니다. Linux x64는 Ubuntu24.04 WSL·glibc2.39에서 빌드·확인하고 `libcurl.so.4`가 필요합니다. Ubuntu24.04의 패키지 이름은 `libcurl4t64`이며 더 오래된 glibc와의 호환성은 확인하지 않았습니다.

새 배포본은 실제 주소·토큰이 없는 설정 예제로 시작합니다. `url`에 포트와 경로를 포함한 전체 API 주소를 입력하세요. 로컬 시험 주소는 `http://127.0.0.1:21000/ingest`입니다. 주기 상태 보고, UDP 백업, 전송률 제어는 필요한 서버·기체에 맞춰 활성화합니다. 기존 운용 설정은 새 예제로 덮어쓰지 않습니다.

HTTP는 JSON POST와204 수신 확인을 사용합니다. UDP 백업은 별도 조각 헤더를 사용하며 수신 확인이나 재전송을 보장하지 않습니다. [서버 API](../SERVER_API.md), [UDP 규격](../UDP_BACKUP.md), [배포 폴더 안내](../../release/README.md)를 참고하세요.

## 보존 범위와 배포 상태

대기 데이터는 RAM에만 있습니다. 프로세스가 종료되면 미확인 데이터는 사라집니다. 버퍼 한도는 대기 JSON과 관리 정보에 적용하며 프로세스 전체 메모리 한도는 아닙니다. 한도가 차면 기존 미확인 데이터를 유지하고 새 TCP 자료의 손실을 표시합니다.

배포본에서 로컬 운용 설정, 인증값, 수집 자료, 개인 경로를 제외합니다. Windows 암호화 토큰은 다른 PC·사용자에게 이전하지 말고 새 환경에서 다시 입력하세요. Linux에서 직접 토큰을 저장하려면0600 권한을 지원하는 파일 시스템이 필요합니다.

게시 저장소는 [VIPSfef/HyRUS_EnvData_Router](https://github.com/VIPSfef/HyRUS_EnvData_Router)입니다. 소스 커밋·태그와 manifest의 소스 상태를 맞춰 배포합니다. 별도 PX4 저장소의 게시·펌웨어 업로드는 이 호스트 릴리스에 포함되지 않습니다. 프로젝트 자체의 라이선스는 아직 선택하지 않았습니다.
