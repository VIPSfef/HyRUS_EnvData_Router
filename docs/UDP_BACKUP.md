# 센서 JSON의 UDP 백업 전송

수락한 새 센서 표본을 HTTP 요청·응답과 독립적으로 바로 송신하고, 같은 자료는 TCP 전송을 위해 메모리에 보관하는 선택 기능이다. QGC의 MAVLink UDP 중계와는 별개다. HTTP 전송 성공 여부와 관계없이 병행하며 UDP 응답·ACK·재전송은 없다. UDP 전송 성공으로 HTTP 대기 자료를 해제하지 않는다. 서버 전체 저장 절차는 [서버 API](SERVER_API.md#2-통신-방식)를 따른다.

## 설정

```ini
url=http://127.0.0.1:21000/ingest
udp_backup_enabled=1
udp_backup_host=auto
udp_backup_port=0
tcp_buffer_max_mb=1024
```

`auto` 호스트는 HTTP URL의 호스트, 포트 `0`은 그 URL의 TCP 포트+1이다. 위 설정의 실제 UDP 목적지는 `127.0.0.1:21001`이다. URL에 포트가 없으면 HTTP는80→81, HTTPS는443→444다. `udp_backup_host`와 `udp_backup_port`를 각각 명시해 바꿀 수 있고 설정 화면43~45번과 재시작을 사용한다. 기본 예제에서는 비활성이다.

IPv4·호스트명·IPv6를 지원한다. DNS는 소켓을 열 때 해석한다. `url=-`에서는 호스트와 포트를 모두 명시해야 한다. TCP65535에는 +1이 없으므로 UDP 포트를 따로 지정해야 한다. URL의 경로·query·Bearer 토큰은 UDP 목적지나 헤더에 포함되지 않는다. HTTPS 설정도 UDP를 암호화하지는 않는다.

## 전송 흐름과 보존 범위

UDP 활성화 시 해독·검증을 통과한 일반 관측과 온습도 표본마다 레코드를 확정한다. ID·세션·원점·시계·표본을 한 번 정하고 같은 인코딩 JSON을 TCP 대기 FIFO에 보관하면서 비차단 UDP 소켓으로 바로 송신을 시도한다. UDP 대기 큐를 쌓지 않고 `send_interval_ms`와 HTTP 응답을 기다리지 않는다. HTTP 작업자는 설정 주기에 고정한 대기 항목을 `max_windows` 단위로 묶되, 요청 완료 후 `http_min_interval_ms`(기본500ms)를 기다려 나누어 전송한다. 측정·상태·재시도도 이 HTTP 간격을 공유한다. 도중에 새로 들어온 항목은 다음 라운드에 처리하고, 실패하면 남은 항목을 보존한다. UDP 비활성화 시에는 기존 시간 구간·전송 주기에 따른 배치 수집을 유지한다.

HTTP401·403·429에 따른1..30초 재시도 대기는 UDP에 적용하지 않는다. HTTP 요청률 제한이나 무응답 때문에 UDP 백업을 멈추지는 않는다. 반대로 UDP 송신 성공은 HTTP의 대기·재시도·미확인 자료 보존 규칙을 바꾸지 않는다.

표본별 즉시 확정은 실시간 `schema:3`과 온습도에 적용한다. 개발용 CSV `schema:2`는 중복 키가 `window_us`이므로 UDP를 켜도 측정 시간 구간 단위로 묶고, 배치 확정 시 송신한다. 하트비트 시험과 주기 상태 보고는 각 모드의 생성 주기를 유지한다.

TCP FIFO는 `tcp_buffer_max_mb=1024`가 기본이며 1MiB 단위이므로 기본 1GiB(1,073,741,824바이트)다. TUI46번 또는 설정 파일로 수정한 뒤 재시작 적용한다. 범위는1..65,536MiB이며 32비트 빌드는 최대4,095MiB다. 보류 JSON과 노드 관리 정보의 합계를 제한하며, 처음부터 1GiB를 예약하지 않고 필요할 때 할당한다. HTTP204를 받은 요청의 항목만 해제한다. 수집·UDP·HTTP 작업 버퍼와 OS/TLS 메모리는 별도이므로 프로세스 전체 메모리 상한이 아니다.

HTTP가 무응답이거나 오류를 반환하면 기존 항목을 보존해 재시도한다. TCP 한도 도달·할당 실패에는 새 TCP용 항목을 거부하고 손실을 표시하며, UDP는 계속 송신을 시도한다. 디스크나 파일에 관측을 저장하지 않으므로 프로세스 종료·전원 차단 시 RAM의 대기 자료는 사라진다.

소켓 송신은 비차단이고 실패한 전송을 재시도하지 않는다. 소켓 미준비·커널 버퍼 포화·인코딩 실패 등을 누락/오류 카운터에 표시한다. `sent`는 모든 조각을 로컬 소켓에 넘겼다는 뜻이며 서버 수신 확인이 아니다. 모든 수락 표본의 즉시 송신 시도와 무손실 도착 보장은 다르다.

`status_interval_ms`가 설정돼 있으면 센서 무수신 중에도 같은 UDP 경로로 상태 보고를 보낸다. HTTP 상태 보고와 인코더·순번 발급기를 공유하지만 각각 별도 시각의 스냅샷이다. 상태의 `sample_count=0` 의미는 동일하다.

## JSON 본문

재조립된 본문은 [서버 API](SERVER_API.md)의 기존 JSON 형식이다. 온습도는 `mavlink_weather_v1`, 일반 관측은 숫자3, 개발용CSV는 숫자2, 하트비트 시험은 `mavlink_router_test_v1`, 상태는 `mavlink_router_status_v1`이다. UDP는 확정된 레코드별로 보내며 HTTP처럼 여러 종류를 bundle로 합치지는 않는다.

HTTP와 UDP에서 같은 측정 레코드를 받을 수 있으므로 [서버 API 9절](SERVER_API.md#9-서버의-저장중복-처리-절차)의 개별 레코드 세션·소스·ID로 중복을 처리한다. HTTP가 여러 레코드를 하나의 요청에 합쳐도 각 레코드의 ID와 측정 내용은 바뀌지 않는다. 전체 요청 hash나 UDP 헤더의 전송 순번을 관측 중복 키로 사용하지 않는다. 공간 구간은 더 큰 revision으로 교체한다. 동일 ID의 다른 관측 내용은 정상 중복으로 덮어쓰지 않는다.

UDP로 먼저 저장한 자료가 HTTP로 다시 오면 관측을 중복 추가하지 않고, 그 HTTP 요청의 모든 항목이 저장된 것을 확인한 뒤204를 반환한다. 이 응답이 없으면 수집기는 TCP 사본을 계속 보존한다. 완성되지 않은 JSON이나 STALE 상태 값을 새 측정으로 저장하지 않는다. UDP와 HTTP의 도착 순서는 보장되지 않으므로 늦게 도착한 과거 자료가 최신 상태를 덮어쓰게 하지 않는다.

## 데이터그램 헤더 v1

각 데이터그램은40바이트 헤더와 최대1160바이트 JSON 조각이다. 전체 최대1200바이트이며, 이 크기가 모든 네트워크 경로의 MTU를 보장하지는 않는다. 정수는 모두 네트워크 바이트 순서(big endian)다. HTTP 헤더나 URL은 포함하지 않는다.

| offset | 길이 | 필드 |
|---|---|---|
| 0 | 4 | ASCII `MTRU` |
| 4 | 1 | version=1 |
| 5 | 1 | kind=0(JSON) |
| 6 | 2 | header_bytes=40 |
| 8 | 8 | 실행 nonce |
| 16 | 8 | 전송 시도 순번 |
| 24 | 4 | 전체 JSON 바이트 수 |
| 28 | 4 | 조각의 JSON 내 바이트 offset |
| 32 | 2 | 조각 index(0부터) |
| 34 | 2 | 전체 조각 개수 |
| 36 | 2 | 이번 조각 payload 바이트 수 |
| 38 | 2 | reserved=0 |
| 40 | 가변 | UTF-8 JSON의 바이트 조각 |

조각 개수는 `ceil(total_bytes/1160)`, offset은 `index*1160`이며 마지막 조각만 짧을 수 있다. UTF-8 문자가 조각 경계에서 나뉠 수 있으므로 바이트 재조립 후 해독한다. 한 JSON의 최대 크기는2MiB다. 전송 nonce/순번은 JSON 내 관측 ID와 다른 전송 식별자다.

수신기는 발신 IP·UDP 포트·nonce·전송 순번으로 조각을 구분한다. 참조 구현은 최대4개 조립 상태, 첫 조각부터2초 제한, 범위·길이·개수 검사, 역순 조각과 같은 조각의 재도착을 처리한다. 누락된 조각이 있으면 전체 본문을 버리며 부분 JSON을 전달하지 않는다. CRC나 인증용 서명은 별도로 추가하지 않는다.

## 시험 서버

```text
mavlink_telemetry_data_router_test_server --bind 127.0.0.1 --port 21000
```

기본적으로 HTTP21000과 UDP21001을 함께 받는다. `--udp-port 22001`로 바꾸거나 `--udp-port 0`으로 끈다. TCP65535 사용 시 UDP 포트를 명시해야 한다. 느린 HTTP 클라이언트를 처리하는 중에도 UDP를 처리한다. UDP 소켓을 열지 못하면 HTTP는 유지하고 UDP 오류를 알린다.

시험 서버는 기존과 같이 온습도·시험·상태 형식을 검증하여 표시한다. 일반 관측·bundle 수신/저장 운영 서버를 대체하지 않는다. 두 전송 경로에서 받은 동일 레코드의 화면 중복을 최근의 제한된 기록으로 억제하며, 이는 영구적인 중복 제거 저장소가 아니다. HTTP 재시도만으로 들어오는 기존 요청 집계 의미는 유지한다.
